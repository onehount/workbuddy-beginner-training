# 提示词 05 · 活动安排通知

> **课程中快速带过的案例。** 对应 PPT 第 34–35 页，讲师应明显加快节奏。

| 项 | 内容 |
|---|---|
| **使用时机** | 会议纪要已确认，行动事项已明确 |
| **输入文件** | 已确认的会议纪要（只取已确认的行动事项）<br>`09_活动通知模板.docx` |
| **输出** | 8 月市场活动安排通知 docx |
| **确认节点** | ⚠️ 待确认事项绝不能写成正式决定 |

---

## 可复制提示词

```text
请根据已确认的会议行动事项，按照活动通知模板，生成 8 月份市场活动安排通知。

通知必须包含：
- 通知对象；
- 活动名称；
- 主要任务；
- 负责人；
- 时间节点；
- 材料提交要求；
- 反馈方式。

不得把待确认事项写成正式决定。
```

---

## 为什么这一步最快

前面已经做完了最难的部分：

```
会议纪要
  └─ 已确认决定  ──┐
  └─ 行动事项    ──┼──→ 通知只是换个格式重新排列
  └─ 待确认事项  ──┘（这部分不进通知）
```

**通知不需要重新解释全部背景。** 收件人是参会的人和执行的人，他们知道上下文。

> 💡 **课堂上要说这句：**
> 前面纪要做扎实了，通知就是 30 秒的事。
> 如果通知写得很痛苦，说明纪要没做好 —— 回去补纪要，别硬写通知。

---

## 通知的七个必备要素

| 要素 | 缺了会怎样 |
|---|---|
| **通知对象** | 收件人不知道这事跟自己有没有关系 |
| **活动名称** | 后续沟通对不上号 |
| **主要任务** | 知道有活动，不知道要干嘛 |
| **负责人** | 出问题找不到人 |
| **时间节点** | 所有人都拖到最后一天 |
| **材料提交要求** | 收上来的东西格式五花八门 |
| **反馈方式** | 有疑问的人不知道找谁 |

---

## 最大的坑：把"待确认"写成"已决定"

### ❌ 错误示范

原始纪要里写的是：

```
待确认事项 3：快闪活动的预算追加金额 —— 记录中提到"再加一点"，无具体数字
待确认事项 5：数据看板的上线时间 —— 记录中提到"尽快"，无明确时间
```

生成的通知却写成：

```
❌ 三、商场快闪活动
     预算已追加，请各位按新预算执行。

❌ 五、数据看板
     将于 8 月中旬上线，请提前熟悉。
```

**后果：** 通知是**正式文件**。发出去之后，"预算已追加"就变成了大家的共识。等财务说没批，你要挨个解释。

### ✅ 正确示范

```
✅ 三、商场快闪活动
     负责人：陈屿
     预算追加金额尚在审批中，具体数字确定后另行通知。
     请先按原预算准备方案，预算调整不影响 8 月 12 日前提交初稿。

✅ 五、数据看板
     负责人：待确认
     上线时间尚未确定，本月内不安排相关任务。
```

## 加固提示词（防止它自作主张）

如果它总是把待确认的事写成确定的，加这一段：

```text
补充要求：
请先列出你从会议纪要中提取的全部事项，并逐条标注它在纪要中属于「已确认决定」「行动事项」还是「待确认事项」。
只有前两类可以写进通知正文。
「待确认事项」如需在通知中提及，必须明确写出"尚未确定""另行通知"或"待确认"字样。
标注完成后，再生成通知。
```

---

## 拿到通知后必查

- [ ] 每一条内容都能在纪要的「已确认决定」或「行动事项」中找到
- [ ] 纪要中标注"待确认"的，通知中没有变成肯定表述
- [ ] 每项任务都有负责人（或明确写"待确认"）
- [ ] 时间节点具体到日期，没有"尽快""近期""下周"
- [ ] 材料提交要求写清了：交什么、交给谁、什么格式
- [ ] 反馈方式写了具体的人和渠道
- [ ] 通知对象范围正确，没有漏人也没有多发

## 常见问题

**Q：通知太啰嗦，把整个会议都复述了一遍**

```text
通知的收件人都参加了会议，不需要重复背景。
请删除所有会议过程描述和数据分析内容，只保留：谁、做什么、什么时候之前、交给谁。
控制在一页以内。
```

**Q：语气太生硬 / 太随意**

```text
请调整为部门内部通知的语气：简洁、明确、不使用命令式措辞，也不使用口语。
标题使用"关于 XXX 的通知"格式。
```
